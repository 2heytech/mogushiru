# モグシル 設計案 v0.2

- 作成日：2026-10-10（v0.2：依頼者の回答を反映）
- ステータス：確定した方針で実装を開始
- 対象：Webブラウザだけで使える、栄養バランスを気軽に楽しく確認するアプリ

---

## 1. コンセプトと方針

**「食べる前に、組み合わせを遊びながら栄養を知る」アプリ。** 記録アプリではなく、献立のシミュレーター。

| 方針 | 内容 |
|---|---|
| 記録しない | 日々のログ機能は持たない。「今日こんな組み合わせだったら？」を試して楽しむ |
| 登録しない | アカウント・サーバーDBなし。設定や保存データはブラウザ内（localStorage）だけ |
| 待たせない | 栄養データは事前計算済みの静的JSONを配信。選んだ瞬間にブラウザ内で再計算 |
| どこでも使える | スマホ優先のレスポンシブ。PCでは2カラムで集計を常時表示 |
| 楽しい | イラストから選ぶ、マスコットの表情でバランスが分かる、ポップで温かいデザイン |

### 3.4 料理ピッカー

- 上部タブ：**料理** ／ **市販品** ／ **食材** ／ **マイ料理**
- 料理のカテゴリ：主食・主菜・副菜・汁物・麺・丼・パン・おやつ・飲み物・お酒
- 区分に応じた並び替え（朝なら「パン・卵・ヨーグルト」が上に来る）
- 各カードはイラスト＋料理名＋kcal。タップで即追加、長押し（PCはホバー）で栄養の簡易表示
- インクリメンタル検索（ひらがな・カタカナ・漢字の揺れを吸収。例：「からあげ」「唐揚げ」）

#### 飲み物（`src/domain/drinks.ts`）

お酒やお茶など、1日に何杯も飲むものを入れやすくするため、飲み物は「何杯（何本）」で数える。

- 飲み物＝料理の「飲み物」「お酒」と、市販品の飲み物・お酒・乳製品のうち mL で数えるもの（100g 基準は1本の量が分かるものだけ。粉やスティックはグラムのまま）
- ピッカーの「すべて」の上に「飲み物」の列（1行の小さなボタンを横に流す。3.8）。最近入れた飲み物 → その区分の定番の順（ひらいている間は並びを変えない）。「ほかの飲み物」で料理タブの飲み物へ
- 飲み物のカードは押すと1杯入る（同じ飲み物がその区分にあれば、その杯数をふやす）。入れたものには「− コップ2杯 ＋」を出して、−と＋で杯数を変える（1杯のときの−は外す）
- 1日の食事の一覧では、飲み物の行に−・＋（−は1杯まで。外すのは×）。押すと杯数と1杯の量を選ぶ窓（料理の飲み物は「材料を変える」で料理のアレンジへ）
- 1杯の量：ふつうの飲み物はカップ150・コップ200・マグカップ250・缶350・ペットボトル500mL、ビール・発泡酒は缶350・中ジョッキ約400（お店でちがう）・ロング缶500・中瓶500mL、缶チューハイは缶・ロング缶。日本酒（合）・ワイン（グラス）・焼酎や梅酒（ロック）・割ったお酒（1杯）は選ばない。市販のお酒は缶のもの（1本の量が250〜600mL か名前で判断）とそれ以外（シングル・ダブル・グラス・1合）
- 量は `MenuItem.portion`（料理は人前、市販品は mL）のままで、1杯の量を `MenuItem.cup` に持つ（1人前・1本の量なら持たない）。杯数は portion と cup から出す
- 最近入れた飲み物は12件まで、そのときの1杯の量とともにブラウザに保存（`recentDrinks`）。次に入れるときは同じ1杯の量で入る

### 3.5 料理アレンジ

```
┌───────────────────────────┐
│ ← 肉じゃが（アレンジ中）            │
│  [イラスト]   312 kcal → 268 kcal       │
│  P 14g  F 9g  C 36g  食塩 1.9g          │
├───────────────────────────┤
│ じゃがいも   ━━━━○━━  150g  [入替]    │
│ 牛肉(かた)   ━━○━━━━   40g  [入替]    │
│ たまねぎ     ━━━○━━━   50g             │
│ にんじん     ━━○━━━━   30g             │
│ しょうゆ     ━○━━━━━   9g              │
│ 砂糖         ━○━━━━━   4g    🗑        │
│ ＋ 食材を追加                            │
├───────────────────────────┤
│ [           この食事に反映           ]   │
│ [元に戻す]  [☆ お気に入りに保存]          │
└───────────────────────────┘
```

- 「入替」は同じ役割の候補を提示（例：牛肉 → 豚肉・鶏むね肉・大豆ミート）。レシピ定義に候補を持たせる。
- 変更前後のkcal・PFCを並べて表示し、効果が分かるようにする。
- いちばん上に「食べる量」（何人前か）を置き、「1.2人前（材料の合計 180g）」と、いまの量を大きく出す。「つくり方」のタブの「作る人数」は材料の表の人数で、食べる量（栄養の計算）とは別（3.8）。
- 食べる量・くらべた結果・材料は、まとめてスクロールする（画面の低いスマホでも材料まで見られるように）。くらべた結果（元のレシピ → 食べる量）は、スクロールしても上に残す。

### 3.6 プロフィール

- 入力：性別、年齢、身長、体重、身体活動レベル（低い・ふつう・高い をイラスト付きで説明）
- 任意：目標（減量・維持・増量）で目標カロリーを±調整
- 任意：ふだんの運動（種類・1回の時間・週の回数。歩く運動は歩数でも入れられる）。運動を入れたときは、身体活動レベルは運動をのぞいた生活の動きで選ぶ（「高い」の説明から運動習慣を外す）
- 未入力でも使える（初期値は「30〜49歳・ふつう」の目安で表示し、入力を促す）
- 入口は右上のボタン1つで、名前は「栄養の目安を設定」（何のために入れるかが分かる名前にした）。幅320pxのスマホでもロゴと並んで収まるように1行にし、いちばん狭い幅（360px未満）では「目安を設定」まで縮める。未入力のあいだは、枠と字をコーラル色にして目立たせる
- 未入力のあいだは、結果の上にも「仮の目安（30〜49歳・女性）で計算中」と、入れた内容がこのブラウザにのみ保存されることを書く
- 窓の名前も「栄養の目安を設定」（もとは「プロフィール」）。中は「基本の設定」（性別・年齢・身長・体重・月経・ふだんの活動量）と「追加の設定」（ふだんの運動・体重の目標・朝昼晩の配分）に分ける（3.8）。PCは窓を広げて左右に並べ、スマホは追加の設定をたたむ。計算した「1日の目安」は、保存・キャンセルと一緒に窓の下にいつも出す

### 3.7 最初の画面と、入力の途中

- 1日の食事が空のときは、最初の画面（`StartChoice.tsx`）を出す。いちばん上に「料理を選ぶだけで、1日の栄養バランスがわかる」、その下に「結果の例」（献立の例を入れたときのカロリー・PFCバランス・気になる点）、「なにから始める？」で、やりたいことから選ぶ入口を出す（3.8・3.18）。入口は「献立の例から選ぶ」（色をぬった主ボタン。献立の例をいちばん上に。2026-11-17）と「自分の食事で試す」の2つで、もとの3つ目「サンプルで結果を見る」は、結果の例の「この例で結果の画面を見る」になった（2026-11-21。3.18）。スマホでも結果の例と入口が最初の画面に収まるように、スマホではモグを見出しの横に小さく、見出しの下の説明文ははぶき、入口は横長の行（絵・名前とひとこと・矢印）をたてに並べる。保存したものがあれば、その下に「保存した食事を呼び出す」
- 入口を選んだあとも、最初の画面にもどれる（2026-11-17。入口を1つ選ぶと、ほかの入口を選びなおせなかったため）
  - もどり口：1日の食事の画面のいちばん上の「‹ 最初の画面にもどる」、左上のロゴ（どの画面からでも）、スマホの下のバーの「メニュー」の中、ブラウザ・スマホの「戻る」。リセットしたときも最初の画面にもどる
  - もどっても、入れた料理は外さない。料理が入っているあいだ、最初の画面のいちばん上に「‹ いまの1日の食事にもどる（14品・2,100 kcal）」を出し、入口の見出しは「新しく始めるなら」にする
  - 料理が入っているときに入口を選んだら、置き換える前に確かめる：「自分の食事で試す」は「いま入っている料理（14品）をすべて外して、空から始めますか？」、結果の例の「この例で結果の画面を見る」（もとの「サンプルで結果を見る」）と献立の例・保存した食事は「いまの1日の食事を「〇〇」に置き換えますか？」
  - 最初の画面と1日の食事は、URL はどちらも `/` のまま、どちらを出しているかをブラウザの履歴の印（`history.state` の screen。`routes.ts` の `MenuScreen`）で持つ。入口を選ぶ・もどるたびに履歴を1つ足すので、「戻る」で1つ前の画面にもどる。献立の例のページから `/#menu=` で来たときは履歴を足さない（「戻る」で、もとのページへ）
  - ダイアログは、ひらいているあいだ履歴を1つ足して「戻る」で閉じられるようにしている（`useDismiss.ts`）。ダイアログをひらいたまま・閉じてすぐに画面を移るとき（確認の「置き換える」、献立の例の窓で献立を選ぶ）に履歴がずれないよう、画面の移動で履歴を足すのは `pushHistory`（`useDismiss.ts`）で行う
  - ひらいたとき（読みこみ直したとき）は、1日の食事が空なら最初の画面、料理が入っていれば1日の食事を出す

### 3.9 食品を名前でさがして栄養素を見る（2026-11-17）

  - 種類の並びは 食材 → 料理 → 市販品。食材には途中の一致しかなく、料理には語の先頭からの一致があるときだけ、料理を先にする
  - 種類の中は、かたまりの順（食材：ふだんの呼び名のあるもの → 料理の材料に使うもの → そのほか。料理：お気に入り → 朝・昼・晩の定番 → そのほか。市販品：自分で登録したもの → そのほか）→ 一致の度合い → 元の並び
  - 料理を選ぶ画面の検索は、2文字までの言葉で先頭の一致があれば途中の一致を出さないが、ここでは出す（「肉」で鶏むね肉、「いも」でじゃがいも、「パン」で食パンを見つけたい）。そのかわり、ふだんの呼び名のある食材を、成分表の細かい分け方の食材（「いのしし 肉 脂身つき 生」など）より先に並べる
- 栄養素の一覧の窓（`FoodDetailDialog.tsx`。計算は `src/domain/foodDetail.ts`）
  - 上から、量（食材・100gあたりの市販品は g を入れるか「1個（50g）」「100g」のボタン、料理・1食あたりの市販品は ½〜2人前）、カロリーとたんぱく質・脂質・炭水化物（カロリーのうちわけの棒つき）、「この量で多くとれる」成分（1日の目安の15%以上を、割合の高い順に3つまで。カロリーと n-6系脂肪酸は入れない）、「とりすぎに気をつけたい」成分（上限の30%以上）、ランキングと同じ26成分の一覧（種類ごと。量と、1日の目安・上限に対する割合。アルコールは入っているときだけ）
  - 量を変えると、すぐその量の値に変わる
  - 値のない成分は 0 にしない：食材は「値なし」と出す。市販品は表示にない成分の行を出さない（ほとんどの商品は、カロリー・たんぱく質・脂質・炭水化物・食塩だけ）。料理は、材料の一部に値がないとき、分かる分だけを足した量に「※」を付ける
  - 窓の下に「1日の食事に追加」（朝・昼・晩・その他）。見ている量のまま足せる（あとで料理を選ぶ画面でさがし直さなくてよい）
  - 割合は栄養の目安（プロフィール）で変わるので、まだ入れていないときは、仮の目安で計算していると添える
- ランキングの行も、押すとその食材の栄養素の一覧がひらく（その成分だけでなく、ほかの栄養素も見たくなるため）。行の右に「›」を付け、一覧の上に「食品を押すと、ほかの栄養素も見られます」と書く

### 3.10 「名前でさがす」と「成分ランキング」を別の画面にし、さがしやすくする（2026-11-17）

3.9 を公開したあと、「食品を調べる」と「成分の多い順のランキング」が同じ画面にあると情報が見にくい・食品の検索をもっとさがしやすくしてほしい、という依頼で、次のように変えた。

  - 最近見た食品：栄養素の一覧をひらいた食品を、新しい順に8件まで（`useAppStore.ts` の `recentLookups`。ブラウザに保存する。「消す」で消せる。成分ランキングからひらいたものも入る。もう無い料理・商品は出さない）
  - 定番の食品：ごはん・食パン・卵・納豆・牛乳 など12の食材（`lookupCards.ts` の `STAPLE_FOOD_IDS`）

- 言葉の読み方を広げる（`src/domain/lookupQuery.ts`）
  - 空白・読点で区切った言葉は、すべてに一致するものをさがす（「カレー レトルト」「鶏 むね」）
  - ふだんの言い方を、データの名前に読みかえていっしょにさがす（しゃけ→鮭、シーチキン→ツナ缶・ツナマヨ、お米→ごはん、ミンチ→ひき肉、パスタ→スパゲッティ、唐揚げ→から揚げ など。`SYNONYMS`）。足すときはこの表に足す。短い言葉に読みかえると、関係のない食品の読みがなの途中に一致しやすいので（「ツナ」と小松菜）、長めの言葉に読みかえる
  - 1つの言葉で何も見つからないときは、2つに分けて両方に一致するものをさがす（「さば缶」→「さば」と「缶」）。そのときは、分けてさがしたことを候補の上に書く
  - 「（）」や「・」で区切られた名前は、区切りごとの言葉としても見る（「ごはん（白米）」は「ごはん」でも「白米」でも、語との一致になる）
- 一致の度合いを4段にして、並びのまぎれを減らす
  - 0：語と完全に一致 → 1：語の先頭が一致 → 2：画面に出る名前の途中に入っている → 3：読みがな・成分表の名前の途中にだけ入っている
  - カタカナ・漢字の2文字までの言葉で、その字が画面に出る名前に入っていない途中の一致（「ツナ」で小松菜（こまつな）・もつ鍋）は、同じ種類にもっと良い一致（0・1）があれば出さない。ひらがなで入れたときは、読みがなでさがしたいことが多いので、そのまま出す
  - 種類の中の並びは、3.9 と同じ「かたまりの順 → 一致の度合い → 元の並び」
- 候補をしぼる・並べかえる
  - 種類（食材・料理・市販品）を選ぶと、その下に、候補のある分け方だけを件数つきで出す（食材：野菜 12・肉 8 …、料理：お気に入り・主菜・副菜 …、市販品：登録した商品・セブン-イレブン・ローソン …・そのほか）。押すと、その分け方だけにしぼる。スマホは横に流す
  - しぼったまま言葉を変えて候補がなくなったら、しぼりこみは外さずに「しぼりこみを外して見る（◯件）」を出す（勝手に外すと、何を見ているか分からなくなる）
  - 並べかえ：おすすめ順（上の並び）・カロリーが低い順・たんぱく質が多い順（候補の行に出している量あたり。値のないものはうしろ）
  - さがす欄の中の例は、しぼっているあいだは「野菜の中でさがす」のように変える
- 候補の名前の中の、入れた言葉と同じところに色をつける（ひらがな・カタカナ、全角・半角のちがいは同じとみなす。読みがなや別の呼び名で一致したところには、名前の中にないので付けない）
- 候補の行のたんぱく質・脂質・炭水化物は、ひとかたまりで折り返す（幅のせまい画面で1つだけ次の行に落ちない）

### 3.11 検索エンジンに読まれやすくする（2026-11-18）

公開して1週間、Google に登録されたページが 305 ページのうち 100 ページにとどまっていた。Search Console でページを1つずつ調べると、noindex や canonical のまちがいはなく、残りは「まだ読みに来ていない」料理のページだった。Google は6日間で HTML を約540回読みに来ていたが、その多くが次の2つに使われていたので、そこを直した。

- 読みもののページからアプリを開くリンクを、`?` から `#` に変えた（`routes.ts` の `rankingAppPath`・`idealMenuAppPath`・`dishAppPath`）
  - 以前は `/?menu=<献立>`・`/ranking/?n=<成分>`・`/customize/?dish=<料理>`。検索エンジンには、献立・成分・料理の数（あわせて約380）だけ別のページに見え、読みに来ていた（Search Console では「ページにリダイレクトがあります」）。中身はどれもアプリの同じ画面で、登録はされない
  - `#` のうしろは別のページとして数えられないので、`/#menu=<献立>`・`/ranking/#n=<成分>`・`/customize/#dish=<料理>` にした。アプリは `#` のうしろを先に読み、なければ `?` を読む（`appLinkParam`。以前のリンクもそのまま開ける）。読み終えたらアドレス欄から消すのは同じ（`withoutAppLinkParam`）
  - 読みもののページに `?` つきの内部リンクを足さない（`sitePages.test.tsx` で確かめている）
- 献立の例のページ（`/menus/<ジャンル>/`）の料理の名前から、作り方のページ（`/dishes/<料理>/`）へリンクした（作り方のページがある料理だけ。`menuPages.tsx` の `DishPaths`）。読む人は作り方を見に行け、検索エンジンには料理のページへの道がふえる
- http のページを https に送る設定は、配信の側（Cloudflare の「常に HTTPS を使用」）でする。オフのままだと `http://` でも同じページが開き、検索エンジンが http と https の2通りで読む（ここは静的なファイルの配信だけなので、リポジトリの中の設定では送れない）

あわせて、`sitemap.xml` に更新日（`lastmod`）を入れた。検索エンジンは、更新日が実際と合っているサイトの日付だけをあてにするので、ビルドした日ではなく、ページの中身が実際に変わった日を書く。

- ページごとに、中身の指紋と、その中身になった日を `data/sitemap-lastmod.json` に持つ（`scripts/lib/pageLastmod.ts`）
  - 指紋で見るのは、タイトル・説明文・本文（`main` の中）。どのページにもあるところ（上のロゴ・フッター）と、見た目だけの指定（class）は見ない（そこを直しただけで全ページが「更新」にならないように）
  - はじめの日付は、過去のコミットを1つずつ書き出して、指紋が最後に変わった日（日本時間）を入れた
- 中身を変えたら `npm run sitemap:lastmod`（`scripts/update-lastmod.ts`）。指紋が変わったページと新しいページだけ、日付がその日になる。表が古いままだとテスト（`pageLastmod.test.ts`）が落ちる
- ビルド（`scripts/prerender.tsx`）は表の日付をそのまま書く。表と合っていないページがあったときだけ、そのページをビルドした日にする
- アプリの画面（`/`・`/foods/`・`/ranking/`・`/customize/`・`/about/`）は、中身をプログラムが作るので、指紋は最初の HTML に入る字（タイトル・説明文・見出し・リンク）だけ。画面の中身を大きく変えたときは `npm run sitemap:lastmod -- --touch <パス>` で日付をその日にする

#### 料理の作り方のページのレシピのデータ（2026-11-18）

料理の作り方のページ（`/dishes/<料理>/`）には、検索エンジン向けのレシピのデータ（schema.org の Recipe。`dishPages.tsx` の `dishRecipeJsonLd`）を入れている。Search Console から「あるとよい項目がない」と知らせが来たので、ページにある中身から書けるものを足した。

- 料理の種類（`recipeCuisine`）：和食・中華料理・洋食・イタリア料理など。料理ごとに `dishCuisine.ts` の一覧で決め、ページの見出しの上にも「和食・主菜の作り方」のように出す
  - 作り方のページを足したら、その料理を一覧のどれかに足す（一覧とページが合っていないとテストが落ちる）
  - 日本で生まれた洋風の料理（オムライス・とんかつ など）は「洋食」、日本の中華（ラーメン・天津飯 など）は「中華料理」
- キーワード（`keywords`）：おもな材料（はじめのほうの材料を3つまで。調味料・油・砂糖・酒はのぞく）、かかる時間（「15分以内」など。30分をこえる料理には付けない）、栄養の特徴（1人前のたんぱく質が 20g 以上・200kcal 以下）。主菜・和食などの種類とは重ねない
- 手順（`recipeInstructions`）：手順ごとに、名前（`name`。手順のはじめの1文）と、ページの中のその手順へのリンク（`url`。`#step-1` から）を入れる。ページの手順にも同じ id を付けている
- 入れないもの：動画（`video`）、評価（`aggregateRating`）、手順ごとの写真。ページにないものをデータにだけ書くと、うそのデータになる。この3つは Search Console に「あるとよい項目」として残るが、登録のさまたげにはならない

### 3.12 成分ランキングのページを、検索からクリックされやすくする（2026-11-18）

Search Console を見ると、検索結果に出はじめた言葉のほとんどが、成分ごとのランキングのページ（`/nutrients/<成分>/`）に来る言葉だった（「ビタミンcの多い食べ物」「カルシウム 食品ランキング」「マグネシウム食品」「ビタミンb6 食材」など）。ただし、順位は平均で40位前後、クリックは0。公開して1週間なので順位が上がるには時間もかかるが、ページの側でできることをした。

- タイトルと見出し：さがす人の言葉に合わせて「〜が多い**食べ物・食品**ランキング」ではじめる（`nutrientCopy.ts` の `heading`）
  - さがす言葉は「食べ物」と「食品」がほぼ半々で、これまでのタイトルには「食品」しかなかった。「食材」は、はじめの文に入れる（`things`）
  - カロリーは「カロリーが高い」、塩分は「塩分が多い」（「塩分 多い 食べ物」でさがされるので、見出しでは「（食塩）」をはさまない）、カフェインは「飲み物・食品」。オメガ3・オメガ6は「オメガ3脂肪酸（n-3系）」と続けて書く
  - タイトルのうしろは、ここならではのくらべ方（「1回の量・100gあたりでくらべる」）。共有の画像の見出しは24字までなので、短い言い方（`short`）を使う
- 説明文：上位3つの名前と量からはじめる（「1位 パプリカ（赤） 119mg、2位…」）。検索結果には、はじめの60字ほどしか出ないことも多い
- ページの並び：ランキングをいちばん上にし、1日の目安の表はそのあとにした（さがしに来た人がまず見たいのはランキング）。表の見出しは「〜の1日の摂取量の目安」（「摂取量」でさがす人がいる）
- 食品の種類べつの上位（`groupLists`）：野菜・果物・魚介などの種類ごとに、1回の量で多い順の上位5品。「ビタミンCが多い野菜」「カルシウムが多い牛乳・乳製品」のような見出しにする
  - 種類は6つまで。その種類で3番めに多い食品の量を「その種類の多さ」として多い順に並べ、いちばん多い種類の2割に届かない種類は出さない（1品だけ飛びぬけて多い種類が上に来ないように）
  - 2種類に満たないとき（カフェインは飲み物だけ）は出さない
- その成分が多い料理（`dishList`）：作り方のページがある料理を、1人前の量で多い順に10品。名前から作り方のページへ行ける（5品に満たない成分には出さない）
- 料理の作り方のページ（`/dishes/<料理>/`）の「1人前の栄養」に、「この料理に多い栄養素」を足した（`dishPages.tsx` の `richNutrients`）。たんぱく質・食物繊維・ミネラル・ビタミンのうち、1人前で1日の目安（30〜49歳女性）に対する割合の大きい順に3つまで（2割に届かないものは出さない）。名前から、その成分のランキングのページへ行ける
  - 成分のページへのリンクは、これまで成分の一覧と成分どうしだけだった。料理のページからもリンクが向くようにする
- 入れなかったもの：ランキングの一覧のデータ（schema.org の ItemList）。Google が検索結果に使うのは、レシピなど決まった種類の一覧で、1つずつにページの URL がいる。食品ごとのページはないので、入れても検索結果は変わらず、Search Console に「項目がない」と出るだけになる

### 3.15 検索結果での見え方と、検索の土台を直す（2026-11-21）

公開して10日、Google には成分・献立のページと料理のページの一部が登録されているが、検索結果ではタイトルの後ろが落ちたり、古い URL（`http://`・`?n=` つき）が残ったりしていた。4つのレビュー案をまとめた改修計画（第3版）にそって、まず検索の土台と、登録ずみのページの「見え方」を直した。料理のページは別の項（栄養を主役にする）で直す。

- 以前の `?` つきの URL を、読みもののページへ 301 で送る（`worker/index.ts`、決まりは `routes.ts` の `legacyQueryRedirect`）
  - `/ranking/?n=<成分>` → `/nutrients/<成分>/`（成分のページの「くらべ方や種類を変えて見る」は `/ranking/#n=<同じ名前>` なので、名前はそのまま対応する）
  - `/customize/?dish=<料理>` → `/dishes/<料理>/`（そのページがあるときだけ。計画にはないが、改修前の検索実績で `http://…/customize/?dish=tenshinhan` が表示回数の上位に残っていたので、同じしくみで送る）
  - `#` の指定（`/ranking/#n=…`）と、指定のない URL は、これまでどおりアプリの画面を出す
  - 静的なファイルの配信（`_redirects`）は `?` のうしろを見分けられないので、小さなプログラムにした。動くのは `/ranking/` と `/customize/` だけ（`wrangler.jsonc` の `assets.run_worker_first`）。ほかのページは、これまでどおりファイルをそのまま返す。`_headers` の設定は、プログラムを通ったページにも付く（手元の `wrangler dev` で確かめた）。プログラムが自分で作る 301 の答えには付かないので、https で開かせる設定（HSTS）と nosniff は、プログラムの中で同じ値を付ける（`REDIRECT_HEADERS`。2026-11-28 の点検で足した）
- `/ranking/`（並べ替える道具の画面）を検索に載せない（`routes.ts` の `NOINDEX_VIEWS`）
  - 成分ごとの読みもののページ（`/nutrients/<成分>/`）と中身が重なるので、検索の受け皿は一覧の `/nutrients/`（食品成分ランキング）にする
  - 最初に返す HTML の `<head>` に `<meta name="robots" content="noindex">` を入れ、サイトマップから外す。プログラムであとから付けたり外したりしない。`robots.txt` では止めない（止めると、検索エンジンが noindex を読めない）。canonical は `/ranking/` 自身のまま
  - 同じアプリのほかの画面（`/`・`/foods/`・`/customize/`・`/about/`）には付けない（`sitePages.test.tsx` で、noindex が付くのは `/ranking/` だけと確かめている）
  - 画面とサイト内のリンク（成分のページの「くらべ方や種類を変えて見る」、一覧の「条件を変えて並べ替える」、アプリの上のメニュー）はそのまま
  - 28日後に、`/nutrients/` が受け皿になっているかを見る。なっていなければ、noindex を外してサイトマップに戻す
- タイトルは、要点を最初の区切りに入れて30字前後にする（Google の表示では、最初の「｜」より後ろが落ちたり途中で切れたりしていた）。見出し（h1）は、タイトルの最初の区切りとそろえる（Google は h1 を表示に使うことがある）

  - コンビニ・市販品の献立：`コンビニ昼ごはんの組み合わせ3例｜セブン・ファミマ・ローソン｜モグシル`（数と店の名前は、いま出している組み合わせから作る）

依頼は「食材の栄養素だけを調べたいときに使いにくい。鹿肉の栄養素を調べて牛肉とくらべたい。料理ではなく食材を、鹿肉という漢字や、しか、というひらがなでも検索できるようにしたい。近い食材との比較機能もほしい」。それまでは、「鹿肉」は0件、「しか」は読みがなの途中にたまたま「しか」の入るヨーグルト（脱脂加糖＝だっ**しか**とう）が先に出て、鹿肉は成分表のままの名前（しか にほんじか 赤肉 生）で後ろにあった。食材どうしを並べて見る場所もなかった。

- 食材を、漢字・ひらがな・カタカナのどれでもさがせるようにする
  - 成分表の名前はひらがな（しか・うま・いのしし・めんよう）なので、漢字や別の呼び名を足した：`data/food-aliases.json`（約280の決まり。肉・内臓・魚・貝・野菜・果物・きのこ・海そう・穀物・調味料・菓子）。`data/food-names.json` の `synonyms` と同じ形で、`scripts/import-mext.ts` が両方を読んで `foods.json` の読みがな（`kana`）に足す。アプリには入れない（`foods.json` を作るときだけ使う）
  - 決まりに `"word": true` を付けると、成分表の名前の語とぴったり同じときだけ足す（`scripts/lib/food-names.ts` の `nameWords`）。「うし → 牛肉」は、これがないと「きゅ**うし**ゅうじか」（鹿）にも付いていた
  - 鹿肉・馬肉・いのしし・ラム・くじら・牛タン・ハラミ・ホルモンなど62品に、呼び名を付けた（`data/food-names.json` の `moreNames`。「鹿肉（にほんじか・赤身）」「牛タン（生）」）。ふだんの呼び名（`displayNames`）と分けたのは、`displayNames` が成分ランキングの「よく使う食品」（3.13）のもとになっているため。`moreNames` は、名前でさがすときと、くらべる相手を選ぶときにだけ使い、ランキングには入れない（`ranking.ts` の `MORE_NAMED_FOOD_IDS`）
- さがした結果の並び（`src/domain/lookupQuery.ts`、`src/components/lookupCards.ts`）
  - 食材のかたまりは、ふだんの呼び名のあるもの → `moreNames` → 料理の材料 → そのほか、の4つ（`foodLookupGroups`）。`moreNames` を1つめに入れないのは、成分表の名前に「肉」という語のあるもの（うま 肉 赤肉 生）が、「肉」でさがしたときに鶏むね肉・牛もも肉より先に出てしまうため
  - 一致の度合いに 4 を足した：画面に出ない読みがな・別名の途中にだけ入っているもの。どのかたまりのものも、最後にまとめる（「しか」で、鹿肉が先、ヨーグルトは後ろ）
  - 短い言葉（2文字まで）を漢字・カタカナで入れたときは、名前にその字のまま入っているもの・別名とぴったり同じものを先にする（「馬」で、別名が馬鈴薯のじゃがいもより馬肉。「牛肉」で、別名が牛肉の牛もも肉は、名前に「和牛肉」のある成分表のままの食材より先）
  - 「鹿肉 カロリー」「鹿肉の栄養」のように、検索サイトと同じ入れ方をしても見つかる（「カロリー・栄養・成分・比較」などは、ほかに言葉があれば読みとばす。空白なしで後ろに付けたときは、見つからないときにだけ外す）
  - 「鹿肉 牛肉」のように、すべてをふくむものがない2つ以上の言葉は、どれかをふくむものを、入れた順に出す（どの言葉も、それだけなら見つかるときだけ）。食材が2つ以上選べるときは、「この食材を並べてくらべる」のボタンを出す（`comparePicks`。1つめはその言葉の先頭の食材、2つめからは、その言葉で見つかる中で1つめに近いもの。鹿肉の赤身なら、牛ひき肉ではなく牛ももの赤身）
- さがす種類を、先に決められるようにする（`FoodLookup.tsx`）
  - さがす欄の下に「すべて・食材・料理・市販品」の切り替えを、さがす前から出す（それまでは、さがした結果に2つ以上の種類があるときだけ出ていた）。「食材」を選ぶと、食材だけをさがす。選んだ種類は、言葉を消しても、変えるまでそのまま（さがす欄の例・さがす前の説明・「種類からさがす」も、その種類だけにする）
  - 選んだ種類に候補がなく、ほかの種類にはあるときは、「〜の中には見つかりませんでした」と、「しぼりこみを外して見る」のボタン
- 近い食材と並べてくらべる（`src/domain/foodCompare.ts`、`src/components/FoodCompare.tsx`）
  - 入口は3つ：食材の栄養素の一覧（`FoodDetailDialog.tsx`）の「近い食材とくらべる → 並べてくらべる」、「食品を調べる」のさがす前の画面の「食材をくらべる」、食材の名前を2つ入れたときのボタン
  - 近い食材の選び方（`nearFoods`）：同じ食品群の中から、**ほかの種類の食材を、種類ごとに1つ**。種類は成分表の名前から読む（肉は動物＝うし・ぶた・しか、魚は（〜類）、そのほかは食品と区分＝だいず［豆腐・油揚げ類］）。近さは、100gあたりのカロリー・たんぱく質・脂質・炭水化物の差に、食物繊維・カルシウム・鉄・ビタミンA・C の差を少し足したもの。調理の状態（生・ゆで・焼き・缶詰…）と形（内臓・ひき肉・加工品）が同じものを先に、呼び名のない食材・`moreNames` の食材は後ろにする。鹿肉（赤身）なら、牛もも肉（輸入・赤身）・鶏むね肉（皮なし）・豚もも肉（生）
  - はじめに並べるのは、その食材と、近い食材3つ（`COMPARE_START`）。ほかの種類が足りないときは、同じ食材の部位・状態ちがい（牛もも肉なら牛ばら肉）で埋める
  - 表：26成分を、同じ量で並べる。量は「100gあたり」（はじめ）と「1回の量で」（成分ランキングと同じ「1回に食べる量」）を切り替える。行ごとに、いちばん多い値に色を付け（とりすぎに気をつけたい成分は注意の色）、いちばん多い値を100%とした棒を出す。測られていない成分は「値なし」（0 にしない）
  - 表の上に、1つめの食材を2つめとくらべたときの、ちがいの大きい成分を4つまで言葉で出す（「鉄が多い 3.9mg（2.5mg）」。小さな差は出さない。`compareNotes`）
  - 食材は5つまで（`COMPARE_MAX`）。「×」で外す、「食材を足す」で足す（近い食材・同じ食材の部位や状態ちがいの札を押すか、名前でさがす。さがすのは食材だけ）。食材の名前を押すと、その食材の栄養素の一覧が上に重なってひらく
  - スマホでも横に送らない：列の幅はどの食材も同じ（`table-fixed`）。幅360px から、成分の名前と食材4つが入る（5つめを足すと列がせまくなる）。下へ送っても、食材の名前の行は窓の上に止まる
  - ひらいているあいだのアドレスは `/foods/#compare=<食品番号>,…`（`routes.ts` の `compareAppPath`）。貼ると、同じ食材を並べた窓がひらく。窓を閉じても、並べていた食材は覚えておく（「食材をくらべる」をもう一度押すと続きから。ページを読みこみ直すと忘れる）
  - 料理・市販品は、くらべられない（成分表の食材だけ。料理は材料と量で値が変わり、市販品は値のない成分が多いため）
- テスト：`foodCompare.test.ts`（性質の読みとり・近い食材・表・ちがい）、`lookupCards.test.ts`（配信用のデータで、鹿肉・しか・シカ・鹿・馬・猪・羊・鯨・ハラミ・牛肉の先頭の食材）、`lookupQuery.test.ts`、`routes.test.ts`、`scripts/lib/food-names.test.ts`

### 3.24 成分のページに、楽天市場でさがすリンク（楽天アフィリエイト）を置く（2026-11-27）

依頼は「栄養素のページに、その栄養素に対応する食品の楽天アフィリエイトを追加したい」。運営の費用をまかなうための、はじめての広告。読みもののページの軽さと、数値への信用をくずさない形にした。

（2026-11-28 の追記）欄に出すものは、3.28 で、ランキングの食品から、サプリメントなどの商品の種類に変えた。下の「何を出すか」「さがす言葉」「欄の場所」と、出すページの数（22）は、そのときまでのもの。リンクの形・「広告」の表示・ID の置き場所は、いまも同じ。

- どこに出すか：成分ごとのランキングのページ（`/nutrients/<成分>/`）のうち、とりたい成分の22ページ。「1回の量」の一覧（と種類べつ）のすぐあとに、「〜が多い食品を楽天市場でさがす」の欄（`nutrientPages.tsx` の `ShopLinks`）
  - とりすぎに気をつけたい成分（塩分・飽和脂肪酸・カフェイン）とカロリーのページには出さない（「塩分が多い食品を買う」とすすめることになるため。100円あたりの一覧を出さないのと同じ決まり）
  - 成分の一覧（`/nutrients/`）・料理・献立の例・食品のページと、アプリの画面には出さない
- 何を出すか（`src/pages/rakuten.ts`）
  - 食品は、「ふだん1回に食べる量」のランキングの上から順に8つ（`shopPicks`、`SHOP_SIZE`）。広告のために食品を選んだり、順位や数値を変えたりしない
  - 同じ名前になる食品（鶏むね肉（皮つき・焼き）と鶏むね肉（皮なし））は、上の1つだけ。葉だけでは売られていない食品（大根の葉・かぶの葉）と脱脂乳は出さない
  - 行き先は、楽天市場の検索結果（`https://search.rakuten.co.jp/search/mall/<言葉>/<ジャンル>/`）。商品を1つずつ選んで載せることはしない（値段・在庫・商品のページが変わっても、リンクが古くならない。楽天の商品検索の API も使わない）
  - さがす言葉は、食品の名前からかっこ（「（生）」「（ゆで）」）を取ったもの。成分表の言い方では見つかりにくい食品は、店での言い方を表（`SEARCH`）に書く（オリーブ油 → オリーブオイル、かき → 牡蠣、大豆たんぱく → 大豆ミート、あゆ → 鮎）
  - 検索は食べ物のジャンルにしぼる：食品（100227）。飲み物（食品群16と、牛乳・豆乳・ジュース）は 水・ソフトドリンク（100316）。お菓子・菓子パン（食品群15）は、楽天市場で「スイーツ・お菓子」と「食品」に分かれているので、しぼらない。しぼるのは、名前だけでさがすと、同じ名前の食べ物でないものがまじるおそれがあるため（飲み物を「食品」でさがすと、豆乳ではなく豆乳の鍋つゆなどが先に出た）
  - 入れたときは、22ページに出る100の言葉を、楽天市場の検索で1つずつ確かめた（どれも食べ物が出て、0件はない）。「パプリカ」は粉の香辛料が出るので「パプリカ 野菜」、「くるみ」は「くるみ 無塩」にした
- リンクの形
  - アフィリエイトのリンクは `https://hb.afl.rakuten.co.jp/hgc/<ID>/?pc=<検索結果のアドレス>&link_type=text`
  - 文字のリンクだけ。楽天の画像・プログラム（ウィジェット）は読みこまない。読みもののページは「プログラムを読まない」ままで、読みこんでよい場所の決まり（`public/_headers` の CSP）も変えていない。ページを開いただけでは、楽天には何も送られない
  - `target="_blank"`・`rel="sponsored nofollow noopener"`（検索エンジンに、広告のリンクだと伝える）。どこから来たかを楽天に伝えるため、`noreferrer` は付けない
  - 欄の絵は、このサイトの食品の絵（スマホでは、名前の幅をとるために出さない）
- 広告であることの表示（景品表示法のステルスマーケティングの規制）
  - リンクのあるページは、見出し（h1）のすぐ下に「このページには広告のリンクを含みます。」（`AD_NOTICE`）
  - 欄の見出しと、ページの上の目次の「楽天市場でさがす」に「広告」の印（`AdMark`）
  - 欄の下に、楽天アフィリエイトのリンクであること・買い物をすると運営者に紹介料が入ること・順位と数値は広告と関係なく決めていること・楽天市場に出てくる商品の成分はこのページの値と同じとはかぎらないこと
  - 「このサイトについて」（`/about/`）に「広告」の欄（`#about-ads`）を足し、「プライバシー」に、リンクを押すと楽天が Cookie などで紹介元を記録することを書いた
- アフィリエイトの ID：`src/site.ts` の `RAKUTEN_AFFILIATE_ID`（8桁の英数字を「.」で4つつないだもの）。リンクの中に入って、だれでも見られる値なので、リポジトリに置く
  - 空にする・形がちがうと、欄も「広告」の表示も「このサイトについて」の欄も出ない（`rakutenEnabled`）
  - ビルドのときの変数にしなかったのは、ページの中身が ID のあるなしで変わると、サイトマップの更新日の表（`data/sitemap-lastmod.json`）と合わなくなり、ビルドのたびに「今日更新」になるため
- 足さなかったもの：商品の画像・値段を出す欄（楽天の商品検索の API）。読みもののページでプログラムを動かし、楽天から画像を読みこむことになる（CSP を広げる・ページを開いたときに楽天へ通信する）。クリックの数を見てから考える → 同じ日に依頼があり、3.25 で足した
- テスト：`rakuten.test.ts`（リンクの形・さがす言葉・食品の選び方・ID が空のとき）、`sitePages.test.tsx` の「楽天市場でさがす欄」（22ページに8つずつ・リンクの属性・広告の表示・出さないページ・楽天の画像やプログラムを読みこまないこと・「このサイトについて」の文）

### 3.25 「楽天市場でさがす」の欄に、商品の例を画像つきで出す（2026-11-27）

依頼は「リンクではなく、最初から検索後の画像付きの商品が表示されているようにして」。3.24 の欄は、食品の名前の文字のリンクだけで、押さないと商品が見えなかった。

（2026-11-28 の追記）この仕組みは、アプリ ID を入れるまで動かない。入れるための楽天ウェブサービスの管理画面がメンテナンス中なので、それまでは 3.27 の「前もって選んだ商品の画像」を出す。

- 何を出すか：食品ごとに、楽天市場でその食品の名前をさがした結果の商品を、上から6つまで。商品1つに、画像・名前（2行まで）・値段・「送料無料」（送料こみの商品）・レビューの平均と件数（あるとき）。押すと、楽天市場の商品のページを新しいタブでひらく（アフィリエイトのリンク。`rel="sponsored nofollow noopener"`）
  - 食品の名前のリンク（楽天市場の検索結果へ）は、行の見出しとして残す（「楽天市場でもっと見る ↗」）

  - スマホは、食品ごとに横に送る1列（縦に長くなりすぎないように）。広い画面（md から）は横に6つ

  - さがす言葉とジャンルは、文字のリンクの先（楽天市場の検索結果）と同じ（`ShopPick` の `word`・`genreId`）。画像のある商品・売り切れていない商品だけをもらう（`imageFlag=1`・`availability=1`）

  - 呼ぶのは、欄が画面に近づいたとき（下に800pxまで来たとき）だけ。欄を見ない人の分は呼ばない。欄が画面より上にあるとき（目次から下の一覧へ飛んだとき）は呼ばない（上で欄がのびて、読んでいるところがずれるため）

  - 取れない・商品が2つ未満の食品は、文字のリンクのまま。プログラムが動かない（古いブラウザ・広告を止める拡張など）ときも、文字のリンクがそのまま出る
  - 楽天から来た字は `textContent` で入れる（HTML として読まない）。リンクは https の楽天のアドレス（`rakuten.co.jp` と、その下）だけ、画像は https の `thumbnail.image.rakuten.co.jp` だけを通し、ほかは出さない
  - 見た目は、ページに書いてあるひな形（`<template data-shop-card>`）と、食品（li）に付ける `data-shop-row`（`wait`：読みこみ中、`on`：商品あり）を見るクラスで決める（`nutrientPages.tsx` の `ShopLinks`）。プログラムはクラスを持たない（CSP で style 属性が使えないため）。読みこみ中は、商品が入ったときと同じぐらいの高さをあけておく
  - 商品を出したときだけ見せるもの（`data-shop-on`）：「楽天市場の商品の例を出しています」の説明、「商品と値段は、ページを開いたときの楽天市場の検索結果で、このサイトが選んだものではありません」、楽天ウェブサービスのクレジット（楽天の指定の文字のリンク「Supported by Rakuten Developers」）

- 「広告」の表示：見出し（h1）のすぐ下に「このページには広告のリンクを含みます。」と、欄へ送るボタン（「プロテインなどを楽天市場でさがす ↓」）。欄の見出しに「広告」。ボタンは、ふつうの「#shop」のリンクにしない（アプリは「#」を、成分を選ぶリンク `#n=iron` などに使う）。押すと画面を欄へ送り、見出しに移る
- 欄の部品を1つにした：`src/components/RakutenShelf.tsx`（`RakutenShelf`・`AdMark`・`AD_NOTICE`）。成分ごとのページ（`nutrientPages.tsx`）とアプリの両方が使う。状態を持たないので、読みもののページの HTML は前と同じ（ビルドの前後で、成分のページ26まいの HTML が変わらないことを見た）
- 商品の画像：前もって選んだ商品（3.27・3.28）。画像は、欄が画面に近づいたときに読みこむ（`loading="lazy"`）ので、一覧だけを見て閉じる人のブラウザからは、楽天のサーバーへの通信が出ない
- 楽天市場商品検索 API で出す設定（3.25。まだ動かしていない）のあいだは、この画面の欄は、種類の名前のリンクだけにする（`pictures={false}`。`public/rakuten-shop.js` は読みもののページのためのもので、アプリでは動かさない）。API を動かすときに、この画面でも商品を出すかを決める
- ランキングの順位と数値は、広告のために変えない（欄の中にも書いてある）
- アプリのプログラムが、前もって選んだ商品の表（`data/rakuten-picks.json`）の分だけ大きくなる（gzip で 8KB ほど）
- 「このサイトについて」の「広告」：欄のある場所に、成分ランキングの画面を足した
- テスト：`src/components/rankingShelf.test.tsx`（欄のある18の成分で、種類のリンクと商品が成分のページと同じ・リンクの形・知らせと欄の場所・欄のない8つの成分では何も出さない・使う前の注意・楽天のプログラムを読みこまない）

## 4. 「一目でわかる」の見せ方

| 要素 | 表現 |
|---|---|
| カロリー | 横長ゲージ。目標を中心に、±10％を「ちょうどいい」帯として色分け |
| PFCバランス | 3本のバーに目標範囲（帯）を重ねる。範囲内は緑、外れると黄色／赤 |
| 主要栄養素 | 食物繊維・カルシウム・鉄・ビタミンC など8〜10項目を「達成率メーター」で表示 |

## 5. 目標値と計算ロジック

基準は **厚生労働省「日本人の食事摂取基準（2025年版）」** を使う。具体的な数値表は実装時に原典から転記し、`data/targets/` に出典付きで保存する。

### 5.1 目標カロリー（推定エネルギー必要量）

```
推定エネルギー必要量 = 基礎代謝量 × 身体活動レベル
基礎代謝量 = 基礎代謝基準値（性・年齢別, kcal/kg/日）× 体重
```

- 身長・体重の入力があれば上式で個人向けに算出。体重未入力なら食事摂取基準の性・年齢・活動レベル別の参照値を使う。
- 身体活動レベル：低い・ふつう・高い の3段階（食事摂取基準の区分に準拠）。
- 目標（減量／増量）を選んだ場合は ±10〜15％程度の調整を表示（医療的な指導ではない旨を明記）。
- ふだんの運動を入れた場合は、上式に運動の分（1日あたりにならした値）を足してから目標の調整をかける（`src/domain/energy.ts`）。

### 5.1.1 使うカロリーと体重の変化（`src/domain/energy.ts`）

出典：厚生労働省「健康づくりのための身体活動・運動ガイド2023」（メッツ表 p.38〜39、INFORMATION 8「身体活動とエネルギー・栄養素について」）

```
使うカロリー = 基礎代謝 + ふだんの生活（基礎代謝 ×（身体活動レベル − 1））+ 運動
運動（kcal/日） = Σ（メッツ − 1）× 1回の時間(h) × 体重(kg) × 週の回数 ÷ 7
```

- メッツはガイド2023のメッツ表の値。安静時の1メッツ分は基礎代謝・ふだんの生活に入っているので引く（ガイドの早見表と同じ式）。
- 歩数は 1,000歩 ≒ 10分 で時間に直す（ガイド2023「60分の歩行は約6,000歩に相当」）。
- 1日の食事のカロリー（摂取）と使うカロリー（消費）を並べ、1日あたりの差を出す（画面の「体重」タブ、広い画面では まとめ・PFC の下）。
- 体重の変化：体脂肪1kg ≒ 7,000kcal（ガイド2023）。体重が変わると基礎代謝も運動の消費も体重に比例して変わるとして
  `dW/dt = (摂取 − k·W) / 7,000`（k は体重1kgあたりの消費）を解き、1か月（30日）・3か月（91日）・6か月（183日）・1年（365日）後を出す。変化はだんだんゆるやかになり、摂取＝消費になる体重に近づく。
- 体重の変化は、1日ぶんの食事（3.7）と体重の両方がそろったときだけ出す。そろうまでは、何が足りないかと「体重を入れる」を出す（食パン1枚だけ・体重なしで「1年後 −42.7kg」のような数字を出さない）。身長があればBMIも出し、1年後にBMI 18.5を下回る・25をこえるときは一言そえる。
- 食べるカロリーが基礎代謝より少ないときは注意をそえ、基礎代謝の半分より少ないときは計算しない（入れ忘れか、続けられない量）。
- 使うカロリーは、体重が未入力なら参照体重で計算し、その旨を書く。
- 年齢による基礎代謝基準値の変化、水分・筋肉量の変化は扱わない（目安である旨を画面に書く）。

### 5.2 PFC目標（エネルギー比）

| 栄養素 | 目標範囲（例：成人） | 備考 |
|---|---|---|
| たんぱく質 P | 13〜20％ | 50歳以上は下限が上がる（年齢別に保持） |
| 脂質 F | 20〜30％ | 飽和脂肪酸は別途上限 |
| 炭水化物 C | 50〜65％ | アルコールを含む扱いに注意（下記） |

- g換算：P・C は 4 kcal/g、F は 9 kcal/g、アルコールは 7 kcal/g で目標g数を表示。
- 表示上のエネルギー比は、成分表のエネルギー値ではなく上記係数で計算した値を使い、合計100％になるようにする（成分表の八訂はエネルギー算出法が異なるため、比率表示は係数ベースで統一）。カロリー総量の表示には成分表のエネルギー値を使う。

### 5.3 上限アラート

| 項目 | 判定の基準（例） | 根拠 |
|---|---|---|
| 食塩相当量 | 男性 7.5g未満 / 女性 6.5g未満 | 食事摂取基準の目標量 |
| 純アルコール | 男性 40g / 女性 20g を超えると警告、それ未満でも量を表示 | 厚労省「健康に配慮した飲酒に関するガイドライン」（生活習慣病のリスクを高める量） |
| 飽和脂肪酸 | エネルギー比 7％以下 | 食事摂取基準の目標量 |
| カロリー超過 | 目標の +15％ 超 | アプリ独自の目安 |
| 耐容上限量のある栄養素 | ビタミンA・D、鉄、カルシウム等の上限超過 | 食事摂取基準の耐容上限量（通常の食事で超えることは稀だが表示はする） |

- アラートは「どの料理が一番効いているか」を添えて表示（例：「食塩の42％はラーメンのスープ」）。
- 未成年（20歳未満）のプロフィールでは、お酒カテゴリを非表示にする。
- 妊娠・授乳中の付加量は v1 では扱わず、注意書きに留める。

### 5.4 栄養計算

```
料理の栄養素 = Σ（食材の可食部100g当たり成分 × 食材のグラム数 ÷ 100）
1日の合計   = Σ（区分内の料理の栄養素 × 人前倍率）
```

- 基本料理の栄養はビルド時に事前計算して `dishes.json` に持つ（選択時は足し算だけ）。
- アレンジ時はブラウザ内で同じ式を再計算する（食材数十件の足し算なので即時）。
- 成分表の「Tr（微量）」は計算上 0 として扱い、表示に「微量含む」の印を付ける。「-（未測定）」は 0 にせず欠損として扱い、合計に「一部未収録の食材あり」と表示する。
- 食塩相当量は成分表の値をそのまま使う。市販品でナトリウムしかない場合は `食塩相当量[g] = ナトリウム[mg] × 2.54 ÷ 1000` で換算し、換算値である印を残す。

### 5.5 食品成分ランキングの「1回の量」（`src/data/serving-sizes.json`）

- ランキングのはじめの並び順は「1回の量で」（ふだん1回に食べる量にふくまれる量）。量は成分表の食品ごとに、食品群・食品名・状態（ゆで／生／乾）で決める。アプリが決めた目安で、公的な基準ではない。
- 量のもとにしたもの：
  1. 農林水産省「食事バランスガイド」SV早見表の、料理の主材料の重さ（ごはん150g、食パン6枚切り60g、ゆでめん1玉、野菜の小鉢およそ70g、魚60〜70g、肉75〜100g、卵50g、牛乳200g、果物100g など）https://www.maff.go.jp/j/syokuiku/zissen_navi/balance/chart.html
  2. ふつうに売られている1個・1枚・1パック・1缶の重さ（納豆1パック45g、ツナ小1缶70g など）
  3. 計量スプーンの重さ（しょうゆ小さじ1＝6g、油大さじ1＝12g など）
- 粉は大さじ1ほど（そば粉を「ゆでめん1玉」にしない）、めんは ゆで・生・乾 で分ける、魚卵は大さじ1強（イクラを「1切れ」にしない）、うすめて使うつゆ・スープはうすめる前の1食分。
- ラベルは食品の状態と合うように書く。`src/domain/serving.test.ts` が成分表の全食品で、状態とラベルが合うこと・量が大きすぎないこと・使われないルールがないことを確かめる。食品を足したりルールを変えたりしたら、このテストで確かめる。
- 画面とページ（/nutrients/）には、量の決め方をひとことで書く（`SERVING_NOTE`）。

## 6. データ設計

### 6.1 データの層

| 層 | 出典 | 収録 | 用途 |
|---|---|---|---|
| 食品マスター | 文部科学省 日本食品標準成分表（八訂）増補2023年（2026-03-27訂正反映） | 約2,500食品・必要な栄養素のみ | 料理の材料、食材単品の追加 |
| 料理マスター | モグシル独自（成分表の食品番号で材料を定義） | MVP 60〜80品 → 150品程度 | 料理ピッカーの主役 |
| 市販品マスター | Open Food Facts（販売国に日本を含む商品） | 栄養5項目が揃うものから厳選 数百〜千件 | 市販品タブ（MVPから） |
| 目標値 | 日本人の食事摂取基準（2025年版）ほか | 性・年齢・活動レベル別 | プロフィールからの目標算出 |

一般食品の標準値と、市販品の表示値は別ファイル・別型で持ち、混ぜない（取得先メモの方針どおり）。

### 6.2 収録する栄養素（アプリで使うもの）

- 基本：エネルギー(kcal)、たんぱく質、脂質、炭水化物、食物繊維総量、食塩相当量、アルコール
- 上限・詳細：飽和脂肪酸（脂肪酸成分表から）、コレステロール
- ミネラル：カルシウム、鉄、カリウム、マグネシウム、亜鉛
- ビタミン：A（レチノール活性当量）、D、B1、B2、C、葉酸

全項目を配信すると重くなるため、上記に絞る。原表の全項目はリポジトリ内の生成元データとして保持する。

### 6.3 型の定義（TypeScript）

```ts
// 栄養素の値。null = 未測定（0とは区別）
type NutrientValue = number | null;
type Nutrients = {
  energyKcal: NutrientValue; protein: NutrientValue; fat: NutrientValue;
  carb: NutrientValue; fiber: NutrientValue; salt: NutrientValue;
  alcohol: NutrientValue; satFat: NutrientValue; /* …ミネラル・ビタミン */
};

// 食品マスター（文科省 成分表）
type Food = {
  id: string;            // 食品番号（例 "01088"）。文字列で保持
  name: string;          // 原表の食品名
  displayName: string;   // 表示用（例「ごはん（精白米）」）
  kana: string;          // 検索用よみ
  group: string;         // 食品群
  per100g: Nutrients;
  traceFlags?: (keyof Nutrients)[]; // Tr の項目
  unitWeights?: { label: string; grams: number }[]; // 「1個」「大さじ1」など
};

// 料理マスター
type Dish = {
  id: string;
  name: string; kana: string;
  category: 'staple' | 'main' | 'side' | 'soup' | 'noodle' | 'bowl'
          | 'bread' | 'snack' | 'drink' | 'alcohol';
  suggestedSlots: ('breakfast' | 'lunch' | 'dinner' | 'other')[];
  illustration: string;  // /illustrations/nikujaga.webp
  ingredients: {
    foodId: string; grams: number;
    role?: string;                 // 「主たんぱく源」など
    alternatives?: string[];       // 入替候補の foodId
  }[];
  nutrients: Nutrients;  // ビルド時に事前計算（1人前）
};

// 市販品マスター
type Product = {
  jan: string;           // 先頭0を落とさない文字列
  name: string; brand: string;
  basis: '100g' | '100ml' | 'serving';
  servingGrams?: number;
  nutrients: Nutrients;
  source: { name: 'Open Food Facts'; fetchedAt: string; saltConverted?: boolean };
};

// ブラウザに保存するもの
type MyDish = { id: string; baseDishId: string | null; name: string;
                ingredients: Dish['ingredients']; createdAt: string; };
type MenuItem = { kind: 'dish' | 'myDish' | 'product' | 'food';
                  refId: string; portion: number; /* 人前倍率 or グラム */ };
type DayMenu = { breakfast: MenuItem[]; lunch: MenuItem[];
                 dinner: MenuItem[]; other: MenuItem[]; };
type Profile = { sex: 'male' | 'female'; age: number; heightCm?: number;
                 weightKg?: number; activity: 'low' | 'normal' | 'high';
                 goal?: 'lose' | 'keep' | 'gain'; };
```

### 6.4 ブラウザ保存（localStorage）

| キー | 中身 |
|---|---|
| `mogushiru:profile` | Profile |
| `mogushiru:current` | 編集中の DayMenu（再訪時に復元） |
| `mogushiru:myDishes` | MyDish[] |
| `mogushiru:savedMenus` | 名前付き DayMenu[]（お気に入り献立） |
| `mogushiru:schema` | 保存形式のバージョン（将来の移行用） |

### 6.5 データ生成パイプライン（ビルド時）

```
data/raw/        文科省Excel（本表・脂肪酸成分表）、OFF抽出CSV  ← 取得日を記録
   │ scripts/import-mext.ts      Excel → foods.full.json（全項目・原表記を保持）
   │   ＋ data/food-names.json   ふだんの呼び名（displayNames・moreNames）と別名（synonyms）
   │   ＋ data/food-aliases.json 漢字・別の呼び名（鹿肉・馬肉・タン など。3.23）
   │ scripts/import-off.ts       OFF抽出データ → products.json
   ▼
data/recipes/*.yaml              料理の定義（食品番号＋グラム＋入替候補）
   │ scripts/build-dishes.ts     レシピ × 食品 → 料理の栄養を事前計算・検証
   ▼
public/data/foods.json           配信用（必要栄養素のみ・約2,500件）
public/data/dishes.json          配信用（事前計算済み）
public/data/products.json        配信用
```

- `build-dishes` は検証も行う：存在しない食品番号、欠損栄養素の多い料理、1人前kcalが常識外れな料理を警告。
- 配信サイズ目安：foods.json は gzip 後 100KB 前後の見込み（推定。実装時に計測）。初回表示に必要な dishes.json を先に読み、foods.json は食材検索・アレンジを開いた時に遅延読み込み。

## 7. 技術構成

| 項目 | 採用案 | 理由 |
|---|---|---|
| 形態 | 静的サイト（SPA）。サーバー・DBなし | 登録不要・運用費ほぼ0 |
| フレームワーク | React + TypeScript + Vite | 情報が多く、即時再計算のUIを作りやすい |
| 状態管理 | Zustand（localStorage永続化ミドルウェア） | 軽量、保存機能をそのまま実装できる |
| スタイル | Tailwind CSS ＋ デザイントークン | ポップな配色を一元管理 |
| グラフ | 自作のSVGコンポーネント（ゲージ・バー・メーター） | 見た目を自由にでき、ライブラリが不要 |
| 検索 | 事前生成した読み仮名＋ひらがな正規化で前方・部分一致 | 依存を増やさずに表記揺れに対応 |
| データ生成 | Node.js スクリプト（Excel読み込みに SheetJS） | フロントと同じ言語で保守しやすい |
| テスト | Vitest（計算ロジック・目標算出）、Playwright（主要操作） | 栄養計算の正しさを担保 |
| ホスティング | Cloudflare Pages（決定） | 非公開リポジトリから無料で公開できる。GitHub Pagesは非公開リポジトリだと有料プランが必要 |
| PWA | vite-plugin-pwa（第2段階） | オフライン・ホーム画面追加 |

## 8. デザイン

### 8.1 トーン

「ポップで優しく温かい」を、**丸み・やわらかい暖色・手描き風イラスト**で表現する。

| 要素 | 案 |
|---|---|
| 背景 | クリーム色 `#FFF8EE`、カードは白に淡い影 |
| メイン | コーラル `#FF8A65`（ボタン・強調） |
| PFC色 | P：いちご `#F47C7C`、F：たまご `#FFC94D`、C：わかば `#7CC98A` |
| 状態色 | ちょうどいい：ミント、注意：はちみつ、警告：トマト（赤一色にせず柔らかく） |
| 文字 | 丸ゴシック（Zen Maru Gothic または M PLUS Rounded 1c、Google Fonts） |
| 字の色 | 本文はこげ茶 `#5B4636`、補足は `#75604E`。色でぬった面（コーラルのボタンや印）の上の字は濃いこげ茶 `#3D2B1F` にし、白い字は使わない。色つきの字は、ぬりの色のままだと薄いので濃い色にする（コーラル `#B8482A`、緑 `#2C7752`、赤 `#BF3030`） |
| 角丸 | カード 20px、ボタンは全丸 |
| 動き | 料理を追加すると皿に「ぽん」と乗るアニメーション、ゲージがなめらかに伸びる |
| マスコット | 「モグ」：おにぎり（またはお茶碗）モチーフのキャラ。表情3〜5種 |

ダークモードは v1 では対応しない（温かい配色を優先）。将来対応できるよう色はトークン化しておく。

### 8.2 料理イラスト

- シンプルでポップなフラットイラスト（太めの丸い輪郭線・ベタ塗り・カテゴリ色の丸い背景）。今は SVG、AI画像（WebP）に差し替え可。詳細は docs/illustration-style.md。
- MVPで60〜80枚、最終的に150枚程度。
- 作り方（決定）：画像生成AIで統一のスタイル指定（プロンプト）を使って作り、手で整える。スタイル指定は `docs/illustration-style.md` に残し、追加時も同じタッチを保つ。利用する生成AIサービスは、生成物の商用利用が規約で認められているものを選ぶ。
- イラスト未作成の料理は、カテゴリ別の汎用イラスト（お皿・お椀・グラス）で代替して先に機能を出す。
- 市販品はパッケージ写真を使わない（権利の問題）。カテゴリ別の汎用イラストで表示する。

### 8.3 アクセシビリティ

- 色だけに頼らず、範囲外はアイコン（⚠）と文言でも示す。
- タップ領域 44px 以上（小さな補助ボタンでも 36px 以上）、文字サイズ 16px 基準。
- 広い画面（幅 640px 以上）の字は、本文（`text-sm`）15px、補足（`text-xs`）14px、いちばん小さい注記（`text-2xs`）でも 13px（2026-11-21 に 1px ずつ大きくした。3.22）。字と背景のコントラストは 4.5:1 以上。
- スマホ（幅 640px 未満）は字をひとまわり大きくする：注記（`text-2xs`）13→14px、補足（`text-xs`）14→15px、本文（`text-sm`）15→16px、`text-base` 16→17px、`text-lg` 18→19px、`text-xl` 20→21px（`src/index.css`）。余白とボタンの大きさは変えない。字の大きさは `text-2xs`〜`text-xl` で書き、`text-[12px]` のように px で決めない（スマホで大きくならないため）。
- ダイアログはキーボードだけで使える（`src/components/useDialog.ts`）。ひらいたらフォーカスを中に移し、Tab / Shift+Tab は中だけを回り、Esc で閉じ、閉じたらひらいたボタンに戻す。新しいダイアログは `useDialog` の ref を `role="dialog"` の要素（`tabIndex={-1}`）に付ける。

### 市販品の選び方（MVP）

- Open Food Factsの「販売国に日本を含む商品」から、エネルギー・たんぱく質・脂質・炭水化物・食塩相当量（またはナトリウム）の5項目が揃い、基準量（100g／100mL／1食）が明確なものに絞る。
- カテゴリ（おにぎり・サンドイッチ・弁当・パン・カップ麺・お菓子・飲料・お酒など）ごとに件数を確認し、よく食べられるものを優先して収録する。売れ筋の判断には、売上ランキングのデータが使えれば参考にする。
- 1食当たりの量が分からない商品は、100g当たりの値で「g指定」で追加する形にする。
- 商品画像は使わず、カテゴリ別の汎用イラストで表示する。
