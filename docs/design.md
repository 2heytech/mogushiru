# モグシル 設計案 v0.1

- 作成日：2026-10-10
- ステータス：たたき台（実装前のレビュー用）
- 対象：Webブラウザだけで使える、栄養バランスを気軽に楽しく確認するアプリ

---

## 1. コンセプトと方針

**「食べる前に、組み合わせを遊びながら栄養を知る」アプリ。** 記録アプリではなく、献立のシミュレーター。

| 方針 | 内容 |
|---|---|
| 記録しない | 日々のログ機能は持たない。「今日こんな組み合わせだったら？」を試して楽しむ |
| 登録しない | アカウント・サーバーDBなし。設定や保存データはブラウザ内（localStorage）だけ |
| 待たせない | 栄養データは事前計算済みの静的JSONを配信。選んだ瞬間にブラウザ内で再計算 |
| どこでも使える | スマホ優先のレスポンシブ。PCでは2カラムで集計を常時表示 |
| 楽しい | イラストから選ぶ、マスコットの表情でバランスが分かる、ポップで温かいデザイン |

### 3.4 料理ピッカー

- 上部タブ：**料理** ／ **市販品**（第2段階）／ **食材** ／ **マイ料理**
- 料理のカテゴリ：主食・主菜・副菜・汁物・麺・丼・パン・おやつ・飲み物・お酒
- 区分に応じた並び替え（朝なら「パン・卵・ヨーグルト」が上に来る）
- 各カードはイラスト＋料理名＋kcal。タップで即追加、長押し（PCはホバー）で栄養の簡易表示
- インクリメンタル検索（ひらがな・カタカナ・漢字の揺れを吸収。例：「からあげ」「唐揚げ」）

### 3.5 料理カスタマイズ

```
┌───────────────────────────┐
│ ← 肉じゃが（カスタマイズ中）            │
│  [イラスト]   312 kcal → 268 kcal       │
│  P 14g  F 9g  C 36g  食塩 1.9g          │
├───────────────────────────┤
│ じゃがいも   ━━━━○━━  150g  [入替]    │
│ 牛肉(かた)   ━━○━━━━   40g  [入替]    │
│ たまねぎ     ━━━○━━━   50g             │
│ にんじん     ━━○━━━━   30g             │
│ しょうゆ     ━○━━━━━   9g              │
│ 砂糖         ━○━━━━━   4g    🗑        │
│ ＋ 食材を追加                            │
├───────────────────────────┤
│ [元に戻す]  [この献立に反映]  [マイ料理に保存] │
└───────────────────────────┘
```

- 「入替」は同じ役割の候補を提示（例：牛肉 → 豚肉・鶏むね肉・大豆ミート）。レシピ定義に候補を持たせる。
- 変更前後のkcal・PFCを並べて表示し、効果が分かるようにする。

### 3.6 プロフィール

- 入力：性別、年齢、身長、体重、身体活動レベル（低い・ふつう・高い をイラスト付きで説明）
- 任意：目標（減量・維持・増量）で目標カロリーを±調整
- 未入力でも使える（初期値は「30〜49歳・ふつう」の目安で表示し、入力を促す）

## 4. 「一目でわかる」の見せ方

| 要素 | 表現 |
|---|---|
| カロリー | 横長ゲージ。目標を中心に、±10％を「ちょうどいい」帯として色分け |
| PFCバランス | 3本のバーに目標範囲（帯）を重ねる。範囲内は緑、外れると黄色／赤 |
| 主要栄養素 | 食物繊維・カルシウム・鉄・ビタミンC など8〜10項目を「達成率メーター」で表示 |
| 上限系 | 食塩・アルコール・飽和脂肪酸などは「超えたら警告」の別枠 |
| 総合 | マスコット「モグ」の表情（にっこり／ふつう／困り顔）＋一言アドバイス |
| 区分別 | 朝・昼・晩・その他それぞれの小計と、1日に占める割合 |

総合判定（マスコットの表情）は、カロリー差・PFC範囲内の数・アラート数から簡単なスコアで決める。点数そのものは強調しない（楽しさ優先、採点アプリにしない）。

## 5. 目標値と計算ロジック

基準は **厚生労働省「日本人の食事摂取基準（2025年版）」** を使う。具体的な数値表は実装時に原典から転記し、`data/targets/` に出典付きで保存する。

### 5.1 目標カロリー（推定エネルギー必要量）

```
推定エネルギー必要量 = 基礎代謝量 × 身体活動レベル
基礎代謝量 = 基礎代謝基準値（性・年齢別, kcal/kg/日）× 体重
```

- 身長・体重の入力があれば上式で個人向けに算出。体重未入力なら食事摂取基準の性・年齢・活動レベル別の参照値を使う。
- 身体活動レベル：低い・ふつう・高い の3段階（食事摂取基準の区分に準拠）。
- 目標（減量／増量）を選んだ場合は ±10〜15％程度の調整を表示（医療的な指導ではない旨を明記）。

### 5.2 PFC目標（エネルギー比）

| 栄養素 | 目標範囲（例：成人） | 備考 |
|---|---|---|
| たんぱく質 P | 13〜20％ | 50歳以上は下限が上がる（年齢別に保持） |
| 脂質 F | 20〜30％ | 飽和脂肪酸は別途上限 |
| 炭水化物 C | 50〜65％ | アルコールを含む扱いに注意（下記） |

- g換算：P・C は 4 kcal/g、F は 9 kcal/g、アルコールは 7 kcal/g で目標g数を表示。
- 表示上のエネルギー比は、成分表のエネルギー値ではなく上記係数で計算した値を使い、合計100％になるようにする（成分表の八訂はエネルギー算出法が異なるため、比率表示は係数ベースで統一）。カロリー総量の表示には成分表のエネルギー値を使う。

### 5.3 上限アラート

| 項目 | 判定の基準（例） | 根拠 |
|---|---|---|
| 食塩相当量 | 男性 7.5g未満 / 女性 6.5g未満 | 食事摂取基準の目標量 |
| 純アルコール | 男性 40g / 女性 20g を超えると警告、それ未満でも量を表示 | 厚労省「健康に配慮した飲酒に関するガイドライン」（生活習慣病のリスクを高める量） |
| 飽和脂肪酸 | エネルギー比 7％以下 | 食事摂取基準の目標量 |
| カロリー超過 | 目標の +15％ 超 | アプリ独自の目安 |
| 耐容上限量のある栄養素 | ビタミンA・D、鉄、カルシウム等の上限超過 | 食事摂取基準の耐容上限量（通常の食事で超えることは稀だが表示はする） |

- アラートは「どの料理が一番効いているか」を添えて表示（例：「食塩の42％はラーメンのスープ」）。
- 未成年（20歳未満）のプロフィールでは、お酒カテゴリを非表示にする。
- 妊娠・授乳中の付加量は v1 では扱わず、注意書きに留める。

### 5.4 栄養計算

```
料理の栄養素 = Σ（食材の可食部100g当たり成分 × 食材のグラム数 ÷ 100）
1日の合計   = Σ（区分内の料理の栄養素 × 人前倍率）
```

- 基本料理の栄養はビルド時に事前計算して `dishes.json` に持つ（選択時は足し算だけ）。
- カスタマイズ時はブラウザ内で同じ式を再計算する（食材数十件の足し算なので即時）。
- 成分表の「Tr（微量）」は計算上 0 として扱い、表示に「微量含む」の印を付ける。「-（未測定）」は 0 にせず欠損として扱い、合計に「一部未収録の食材あり」と表示する。
- 食塩相当量は成分表の値をそのまま使う。市販品でナトリウムしかない場合は `食塩相当量[g] = ナトリウム[mg] × 2.54 ÷ 1000` で換算し、換算値である印を残す。

## 6. データ設計

### 6.1 データの層

| 層 | 出典 | 収録 | 用途 |
|---|---|---|---|
| 食品マスター | 文部科学省 日本食品標準成分表（八訂）増補2023年（2026-03-27訂正反映） | 約2,500食品・必要な栄養素のみ | 料理の材料、食材単品の追加 |
| 料理マスター | モグシル独自（成分表の食品番号で材料を定義） | MVP 60〜80品 → 150品程度 | 料理ピッカーの主役 |
| 市販品マスター | Open Food Facts（販売国に日本を含む商品） | 栄養5項目が揃うものから厳選 数百件 | 第2段階 |
| 目標値 | 日本人の食事摂取基準（2025年版）ほか | 性・年齢・活動レベル別 | プロフィールからの目標算出 |

一般食品の標準値と、市販品の表示値は別ファイル・別型で持ち、混ぜない（取得先メモの方針どおり）。

### 6.2 収録する栄養素（アプリで使うもの）

- 基本：エネルギー(kcal)、たんぱく質、脂質、炭水化物、食物繊維総量、食塩相当量、アルコール
- 上限・詳細：飽和脂肪酸（脂肪酸成分表から）、コレステロール
- ミネラル：カルシウム、鉄、カリウム、マグネシウム、亜鉛
- ビタミン：A（レチノール活性当量）、D、B1、B2、C、葉酸

全項目を配信すると重くなるため、上記に絞る。原表の全項目はリポジトリ内の生成元データとして保持する。

### 6.3 型の定義（TypeScript）

```ts
// 栄養素の値。null = 未測定（0とは区別）
type NutrientValue = number | null;
type Nutrients = {
  energyKcal: NutrientValue; protein: NutrientValue; fat: NutrientValue;
  carb: NutrientValue; fiber: NutrientValue; salt: NutrientValue;
  alcohol: NutrientValue; satFat: NutrientValue; /* …ミネラル・ビタミン */
};

// 食品マスター（文科省 成分表）
type Food = {
  id: string;            // 食品番号（例 "01088"）。文字列で保持
  name: string;          // 原表の食品名
  displayName: string;   // 表示用（例「ごはん（精白米）」）
  kana: string;          // 検索用よみ
  group: string;         // 食品群
  per100g: Nutrients;
  traceFlags?: (keyof Nutrients)[]; // Tr の項目
  unitWeights?: { label: string; grams: number }[]; // 「1個」「大さじ1」など
};

// 料理マスター
type Dish = {
  id: string;
  name: string; kana: string;
  category: 'staple' | 'main' | 'side' | 'soup' | 'noodle' | 'bowl'
          | 'bread' | 'snack' | 'drink' | 'alcohol';
  suggestedSlots: ('breakfast' | 'lunch' | 'dinner' | 'other')[];
  illustration: string;  // /illustrations/nikujaga.webp
  ingredients: {
    foodId: string; grams: number;
    role?: string;                 // 「主たんぱく源」など
    alternatives?: string[];       // 入替候補の foodId
  }[];
  nutrients: Nutrients;  // ビルド時に事前計算（1人前）
};

// 市販品マスター（第2段階）
type Product = {
  jan: string;           // 先頭0を落とさない文字列
  name: string; brand: string;
  basis: '100g' | '100ml' | 'serving';
  servingGrams?: number;
  nutrients: Nutrients;
  source: { name: 'Open Food Facts'; fetchedAt: string; saltConverted?: boolean };
};

// ブラウザに保存するもの
type MyDish = { id: string; baseDishId: string | null; name: string;
                ingredients: Dish['ingredients']; createdAt: string; };
type MenuItem = { kind: 'dish' | 'myDish' | 'product' | 'food';
                  refId: string; portion: number; /* 人前倍率 or グラム */ };
type DayMenu = { breakfast: MenuItem[]; lunch: MenuItem[];
                 dinner: MenuItem[]; other: MenuItem[]; };
type Profile = { sex: 'male' | 'female'; age: number; heightCm?: number;
                 weightKg?: number; activity: 'low' | 'normal' | 'high';
                 goal?: 'lose' | 'keep' | 'gain'; };
```

### 6.4 ブラウザ保存（localStorage）

| キー | 中身 |
|---|---|
| `mogushiru:profile` | Profile |
| `mogushiru:current` | 編集中の DayMenu（再訪時に復元） |
| `mogushiru:myDishes` | MyDish[] |
| `mogushiru:savedMenus` | 名前付き DayMenu[]（お気に入り献立） |
| `mogushiru:schema` | 保存形式のバージョン（将来の移行用） |

- マスターの料理IDが変わっても壊れないよう、マイ料理は材料（食品番号とグラム）を丸ごと保存する。
- プライベートブラウズ等で保存できない場合も、画面は動くようにする（保存不可の表示のみ）。

### 6.5 データ生成パイプライン（ビルド時）

```
data/raw/        文科省Excel（本表・脂肪酸成分表）、OFF抽出CSV  ← 取得日を記録
   │ scripts/import-mext.ts      Excel → foods.full.json（全項目・原表記を保持）
   │ scripts/import-off.ts       OFF一括データ → products.json（第2段階）
   ▼
data/recipes/*.yaml              料理の定義（食品番号＋グラム＋入替候補）
   │ scripts/build-dishes.ts     レシピ × 食品 → 料理の栄養を事前計算・検証
   ▼
public/data/foods.json           配信用（必要栄養素のみ・約2,500件）
public/data/dishes.json          配信用（事前計算済み）
public/data/products.json        配信用（第2段階）
```

- `build-dishes` は検証も行う：存在しない食品番号、欠損栄養素の多い料理、1人前kcalが常識外れな料理を警告。
- 配信サイズ目安：foods.json は gzip 後 100KB 前後の見込み（推定。実装時に計測）。初回表示に必要な dishes.json を先に読み、foods.json は食材検索・カスタマイズを開いた時に遅延読み込み。

### 6.6 料理レシピの書き方（例）

```yaml
id: nikujaga
name: 肉じゃが
kana: にくじゃが
category: main
suggestedSlots: [lunch, dinner]
illustration: nikujaga.webp
ingredients:
  - { foodId: "02018", grams: 150, role: いも }            # じゃがいも 塊茎 皮なし 水煮
  - { foodId: "11xxx", grams: 40, role: 主たんぱく源,
      alternatives: ["11xxx", "11xxx"] }                  # 牛肉・豚肉・鶏肉
  - { foodId: "06153", grams: 50 }                        # たまねぎ
  # … 食品番号は実装時に成分表から確定
```

- 調理後の状態がある食品（ごはん、ゆで麺、焼き魚など）は、成分表の調理済みの値を優先して使う。
- 揚げ物の吸油、汁物の汁を残す、などは v1 ではレシピ側の材料量で表現する（例：揚げ油 8g）。
- レシピの分量は一般的な家庭料理の1人前を基準に作り、出典やメモをYAMLのコメントに残す。

## 7. 技術構成

| 項目 | 採用案 | 理由 |
|---|---|---|
| 形態 | 静的サイト（SPA）。サーバー・DBなし | 登録不要・運用費ほぼ0 |
| フレームワーク | React + TypeScript + Vite | 情報が多く、即時再計算のUIを作りやすい |
| 状態管理 | Zustand（localStorage永続化ミドルウェア） | 軽量、保存機能をそのまま実装できる |
| スタイル | Tailwind CSS ＋ デザイントークン | ポップな配色を一元管理 |
| グラフ | 自作のSVGコンポーネント（ゲージ・バー・メーター） | 見た目を自由にでき、ライブラリが不要 |
| 検索 | 事前生成した読み仮名＋ひらがな正規化で前方・部分一致 | 依存を増やさずに表記揺れに対応 |
| データ生成 | Node.js スクリプト（Excel読み込みに SheetJS） | フロントと同じ言語で保守しやすい |
| テスト | Vitest（計算ロジック・目標算出）、Playwright（主要操作） | 栄養計算の正しさを担保 |
| ホスティング | Cloudflare Pages（またはVercel） | 非公開リポジトリから無料で公開できる。GitHub Pagesは非公開リポジトリだと有料プランが必要 |
| PWA | vite-plugin-pwa（第2段階） | オフライン・ホーム画面追加 |

### ディレクトリ構成（案）

```
mogushiru/
├─ docs/                 設計・データ出典
├─ data/
│  ├─ raw/               取得した元データ（取得日つき）
│  ├─ recipes/           料理レシピ YAML
│  └─ targets/           食事摂取基準の数値表（出典つき）
├─ scripts/              データ生成・検証スクリプト
├─ public/

│  └─ illustrations/     料理イラスト（WebP）

   │  ├─ nutrition.ts    栄養の合算
   │  ├─ targets.ts      目標カロリー・PFC・上限の算出
   │  └─ alerts.ts       アラート判定
   ├─ store/             Zustand（献立・プロフィール・保存データ）
   ├─ components/        カード、ゲージ、メーター、マスコット等
   └─ pages/             献立ボード、カスタマイズ、プロフィール等
```

## 8. デザイン

### 8.1 トーン

「ポップで優しく温かい」を、**丸み・やわらかい暖色・手描き風イラスト**で表現する。

| 要素 | 案 |
|---|---|
| 背景 | クリーム色 `#FFF8EE`、カードは白に淡い影 |
| メイン | コーラル `#FF8A65`（ボタン・強調） |
| PFC色 | P：いちご `#F47C7C`、F：たまご `#FFC94D`、C：わかば `#7CC98A` |
| 状態色 | ちょうどいい：ミント、注意：はちみつ、警告：トマト（赤一色にせず柔らかく） |
| 文字 | 丸ゴシック（Zen Maru Gothic または M PLUS Rounded 1c、Google Fonts） |
| 角丸 | カード 20px、ボタンは全丸 |
| 動き | 料理を追加すると皿に「ぽん」と乗るアニメーション、ゲージがなめらかに伸びる |
| マスコット | 「モグ」：おにぎり（またはお茶碗）モチーフのキャラ。表情3〜5種 |

ダークモードは v1 では対応しない（温かい配色を優先）。将来対応できるよう色はトークン化しておく。

### 8.2 料理イラスト

- 統一タッチの真上〜斜め45度のフラットイラスト、正方形、背景透過のWebP（1枚 20KB 前後目標）。
- MVPで60〜80枚、最終的に150枚程度。
- 作り方の選択肢：①画像生成AIで統一プロンプトを使って作り、手で整える ②イラストレーターに依頼 ③既存の商用利用可素材集。権利関係が明確な①か②を推奨。
- イラスト未作成の料理は、カテゴリ別の汎用イラスト（お皿・お椀・グラス）で代替して先に機能を出す。
- 市販品はパッケージ写真を使わない（権利の問題）。カテゴリ別の汎用イラストで表示する。

### 8.3 アクセシビリティ

- 色だけに頼らず、範囲外はアイコン（⚠）と文言でも示す。
- タップ領域 44px 以上、文字サイズ 16px 基準。
