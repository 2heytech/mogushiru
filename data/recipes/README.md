# 料理レシピ

基本料理の材料を「文部科学省 成分表の食品番号＋グラム数（1人前）」で定義する。
`npm run data:dishes` で検証と栄養の事前計算を行い、`public/data/dishes.json` を生成する。

- 分量の決め方は3通り。どれで決めたかを各料理のコメントに書く。
  1. **成分表のそう菜の配合割合から**：成分表2015年版 第3章「3 そう菜」の平均配合割合（`data/raw/mext-souzai-2015.json`）を使い、八訂18群の同じ料理の100g当たりエネルギーに合わせて材料の総量を決める。そう菜の成分値は煮汁などの水分を含む完成品の値なので、材料の合計は完成品の重さより少なくなる（加えた水は材料に含めない）。
  2. **成分表に料理そのものがあるもの**：とんかつ、お好み焼き、ケーキなどは成分表の料理・菓子の食品をそのまま1つの材料として使う。
  3. **一般的な家庭料理の分量**：上の2つで決められないものは、このリポジトリで独自に設定した1人前の目安。乾麺→ゆで麺などの換算には成分表の重量変化率を使う。
- `templates-*.yaml` は**料理の型**。「{name}の塩焼き」「{name}のみそ汁」のような型に、成分表の食材（`food`）と量（`grams`）を当てはめて料理を作る。料理IDは「型の名前-variantのid」になる（例：`shioyaki-aji`）。食材を足すときは variants に1行足すだけでよい。展開は `scripts/lib/templates.ts`。
- `kyodo.yaml` は**郷土料理**（自動生成、手で編集しない）。農林水産省「うちの郷土料理」の材料表（`data/raw/maff-kyodo.json`）を、材料名→成分表の対応表（`data/kyodo/ingredients.yaml`）で食品番号に置き換え、分量をグラムに換算して人数で割ったもの。`npx tsx scripts/build-kyodo.ts` で再生成し、取り込めなかった料理と理由は `data/kyodo/report.md` に出る。料理ごとの直し（分類・人数・除外）は `data/kyodo/overrides.yaml` に書く。
  - 調味料は材料表の全量を数える（煮汁に残る分も含むので、食塩はやや多めに出る）。水・揚げ油・だしをとる煮干しや昆布は数えない。だし汁は汁物と麺のときだけ数える。
  - 「適量」「少々」の調味料・薬味は数えない。主な材料の分量が読めない料理、成分表に該当がない材料を使う料理、「作りやすい分量」の料理は取り込まない。
  - 出典表示：農林水産省ウェブサイト「うちの郷土料理」を加工して作成（公共データ利用規約 第1.0版）。アプリでは料理のカスタマイズ画面と画面下の出典に表示する。
- 既存の料理を成分表と照合した結果は `docs/recipe-review.md` にまとめている。
- 調理後の状態がある食品（ごはん、ゆで麺、焼き魚、から揚げなど）は調理後の値を使い、グラム数も調理後の重さで書く。
- 飲料は成分表が100g当たりのため、mLから重さに換算して書く（コメントに元の量を残す）。
- 汁物・麺のつゆは、飲み干す前提の量で書く（食塩の上限アラートが効くように）。
- `alternatives` は「入替」で出す候補の食品番号。
